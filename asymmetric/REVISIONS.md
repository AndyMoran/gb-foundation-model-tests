# Asymmetric cost: revisions

Implementation choices made while writing `score.py`, after the plan was tagged `asymmetric-plan` and before any real run. None changes a set, a forecaster, a ratio, a rule or the headline template.

1. **Published figures for check 1.** The plan names `checkpoint0/results.json`, which holds one-decimal means for the regression, Chronos-2 and LightGBM S1. Its TimesFM entry is the multi-day run, not the one-day forecaster scored here. So the script also reads V1's mean from `lgbm_variants/results.json` (one decimal) and TimesFM one-day's from `weather_study/correction1/correction.json` (`corrected.mae_mw.with_weather`, full precision, checked to 0.01 MW). NESO and the Chronos-2/regression average have no published 960-day mean; theirs are reported, not checked.
2. **Two per-day paths, checked against each other.** `score_tails.per_day` loops over the tails study's own forecaster list, so it cannot score V1 or the average. The script computes its per-day values in its own function for every forecaster, and check 1 confirms that, for every tails forecaster, its daily mean absolute error and peak error equal `per_day`'s to 10⁻⁶ MW on every day.
3. **Recorded hashes.** The published results files had no recorded SHA-256. The script records each one's hash as of writing and refuses to run if any has changed. `days.csv` and `day_inputs.csv` are checked against `tails/days.json`, and V1's forecasts against `lgbm_variants/forecasts.json`.
4. **Matching V1.** V1's start times are parsed to UTC timestamps on both sides before merging, so a difference in text format cannot misalign them. The merge must be one to one and leave no half-hour missing.
5. **A complete day.** As well as every half-hour being finite, a day's half-hour count must equal its local length (46, 48 or 50), and the evening window must hold exactly eight half-hours.
6. **Headline punctuation.** Where the all-half-hours clause lists more than one group of ratios, a semicolon, not a comma, separates it from the cold-peak clause, so the sentence parses. A group of one ratio reads "at 3"; a run reads "from 3 to 10". Where every ratio has the same cold-peak label, the clause ends "at each tested ratio". The break-even sentence states the case in words, the share of draws in it, and the conditional interval or why there is none.
7. **Bootstrap details.** One set of draws (seed 20261122) serves every comparison, set and direction statistic. Case shares are over draws with at least one day in the set; any dropped draws are counted. The slope's interval refits the least-squares line on each draw's resampled days.
8. **Direction details.** Days tied on `t_mean` are ordered by date before the ten groups are cut. Lag-1 autocorrelation uses pairs of consecutive calendar days that are both scored. A run of short or long days breaks at a gap in the calendar or at a day with zero bias. A statistic that is undefined (for example, autocorrelation of a constant) is reported as null.
9. **Comparisons with the average.** "Against both" means two comparisons: the average minus the regression, and the average minus Chronos-2. A negative difference means the average had less weighted error.
10. **Importing the tails script.** `tails/score_tails.py` is loaded by file path under its own name and not modified.
11. **Development runs.** The synthetic check was run while writing the script, and the real-run code was exercised on invented values only. No asymmetric loss has been computed on real forecasts. The loader was run once to confirm that V1 and the average join every one of the 46,080 half-hours; no error or loss was computed.
